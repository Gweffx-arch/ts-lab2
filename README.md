## Порівняльний аналіз систем збірки: Webpack vs Vite

У ході виконання лабораторної роботи було проведено міграцію проекту з Webpack на Vite та виконано їх порівняльний аналіз за ключовими технічними критеріями:

| Критерій | Webpack 5 | Vite |
| :--- | :--- | :--- |
| **Швидкість старту dev-сервера** | ~3.5–4.5 сек (потребує попередньої компіляції та створення бандла в пам'яті) | ~150–250 мс (миттєвий старт завдяки нативним ES-модулям браузера без попереднього бандлінгу) |
| **Швидкість HMR (Hot Module Replacement)** | Помітна затримка при перескладанні модулів графа залежностей | Миттєве оновлення конкретного зміненого модуля без перезавантаження сторінки |
| **Складність конфігурації** | Висока: вимагає ручного підключення лоадерів (`ts-loader`, `css-loader`, `style-loader`), плагінів (`HtmlWebpackPlugin`) та тонкого налаштування виключень | Мінімальна: "out-of-the-box" підтримка TypeScript і CSS без додаткових лоадерів; файл `vite.config.ts` займає лише кілька рядків |
| **Підтримка TypeScript** | Потребує налаштування `ts-loader` або Babel, узгодження з `tsconfig.json` і часто прапорця `transpileOnly` для прискорення | Нативна підтримка транспайлінгу через надшвидкий компілятор `esbuild` за замовчуванням |
| **Робота з UI-фреймворками та стилями** | Потребує ланцюжка `['style-loader', 'css-loader']` та вирішення проблем із типами CSS-файлів | Прямий `import "bootstrap/dist/css/bootstrap.min.css"` працює автоматично без додаткових плагінів |
| **Продакшн-збірка** | Повільніша компіляція, складне налаштування Code Splitting та Tree-shaking | Використовує оптимізований Rollup, створює компактніший бандл за менший час |
| **Суб'єктивна оцінка для невеликих SPA** | Надмірно громіздкий, вимагає багато boilerplate-коду конфігурації | Ідеальний вибір для сучасних проєктів завдяки простоті старту, чистоті налаштувань та високій швидкості розробки |

### Висновок
Для невеликих та середніх SPA-додатків на сучасному TypeScript використання **Vite** є значно більш виправданим та продуктивним рішенням, ніж класичний Webpack, оскільки значно скорочує витрати часу на конфігурацію оточення та забезпечує чудовий Developer Experience (DX).
